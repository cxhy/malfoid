# 系列根目录 + 书子 work

一个系列在 `works/<series-id>-<slug>/` 下有一个根目录，每本书是 `books/book-NN/` 子 work。翻译任务以书为粒度执行，系列根只放系列元数据、术语主表和系列级设定。

## 背景

原先把每个单行本/连载段直接当 work，导致系列关系丢失、跨书术语容易漂、单段目录无法原地扩成整本。交付本身是按学年/书分卷，执行粒度也应当对齐。

## 决定

- 系列根：`series.json`（标题、作者、书列表、顺序、状态）、`glossary.json`（系列主表）、`story_bible.md`（系列级设定）。
- 书子 work：`books/book-NN/`，内部保持现有 `meta.json`、`source/`、`work_temp/`、`translation/` 布局。
- 工具仍接收书子 work 作为 `work_dir`；只有系列级操作读 `series.json`。
- 旧作品保持 `works/<work-id>-<slug>/` 单书目录不变。

## 考虑过的选项

- **整个系列一个 work**：预扫描和分块规模过大，交付分卷要靠标题推断，弃用。
- **每本书一个独立 work**：关系丢失，跨书术语要人工同步，弃用。

## 后果

- 新增系列级寻址层；`works/` 下同时存在系列根和旧单书目录，工具需要能区分。
- 术语主表与书副本之间多一步回并；交付前需要同步。
- 系列级 story bible 需要按书增量合并。
