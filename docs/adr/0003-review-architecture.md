# 审查架构：结构化块 + 证据 + 仲裁，advisory

全书审查按固定 token 预算把连续段落打包成审查块，并行执行；输出结构化 JSON，校验审阅段数；候选问题经有界证据核对，块间矛盾做冲突仲裁；只出建议，不自动改正文。

## 背景

现有校对按段落数指数级切分，块越切越小，模型开始编造问题；自由文本报告没有数量和完整性校验；串行执行让每块耗时远超翻译本身。

## 决定

- 审查块按约 3 个翻译批的 token 预算打包，并发 2（可配置）。
- 输出结构化 JSON：`issues[]`、`reviewed_segments`、`complete`；校验审阅段数与完整性。
- 输出不合法才二分重试，单段重试有上限；块级缓存支持断点续跑。
- 候选问题做最多 2 轮证据核对；块间矛盾做冲突仲裁。
- 只产出建议和报告，不自动改正文；修改由独立修复环节或人执行。

## 考虑过的选项

- **自由文本报告**：无法校验完整性，误报和噪声不可控，弃用。
- **完整 autofix + 影子修改 + 盲复检**：质量上限更高，但会绕过人工审计，且成本高；等 Book 1 跑完看误报率再决定。

## 后果

- 审查产物改为 `translation/review/` 下的结构化 JSON + 人读摘要；旧 `proofread/` 只为旧作品保留。
- 审查块需要稳定的段落引用（依赖 ADR 0002）。
- 并发数受本地模型服务能力限制，默认 2。
