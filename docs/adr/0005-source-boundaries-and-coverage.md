# 源文硬边界分段与译文覆盖率检查

把场景分隔符和行边界纳入段身份，并新增确定性的译文覆盖率报告，用来发现“target 非空但 source 没译完”的段。

## 背景

段状态只保证每段有 target，`verify_book` 只检查空 target、术语、英文残留和标题。翻译模型在长段内遇到 `---` 后停住时，target 仍然非空，交付检查会通过，读者看到的是缺了一段场景。

另外，长段按句切分时忽略行边界，切点可能落在对白中间；润色模型随后会跨段移动引号或合并下一段内容。

## 决定

- 独立 `---` 行是硬边界，接入为 `kind=separator` 的段，target 固定为 `---`，不参与翻译和润色。
- 超长文本段先按行边界切，再按句边界切；单句超预算时保持整句。
- 每段记录 `source_start` / `source_end`，偏移相对规范化后的章文本，供覆盖检查和后续重分段使用。
- `translation_coverage.py` 按章计算 source/target 长度比和句子密度中位数，报告：
  - 极端短 target / 句子密度骤降为 error；
  - 长度比偏离、场景分隔符数量不符、场景尾段句子密度下降为 warning。
- `verify_book` 默认把覆盖率问题作为 warning；`--strict-translation-coverage` 将其升级为 error。交付默认保留 warning 可见，不因 suspect 直接拒交。

## 考虑过的选项

- **只靠模型审查**：审查块按全书连续切分，成本和噪声都高，且不能保证每个漏译段都落在审查窗口内。
- **只用 source/target 长度比**：本次漏译只占 source 约 7%，长度比和章中位数接近，单靠长度比抓不到。
- **把 `---` 留在文本段内**：模型容易在分隔符处停住，且润色会跨场景改结构，弃用。

## 后果

- 新接入的书会多出 separator 段；翻译、润色、审查和交付都要跳过或固定处理该 kind。
- 旧作品保持原段状态，不自动重分段；需要时重新接入，未变段按 source_hash 复用 target。
- 覆盖率 warning 是 suspect finder，不是语义判决；确认漏译仍需人工或模型对照。
