# 审查并发默认值：1（取代 ADR 0003 的默认 2）

审查默认单流执行；并发仍可通过 `--workers` 配置，但默认值改为 1。

## 背景

ADR 0003 记录审查默认并发 2。实际运行中，本地模型端点一次只高效处理一个生成请求：4 路并行翻译把单批拖过 300 秒，全部超时且未写入任何段落；审查块在 2 路并行下同样出现排队和长时间等待。端点本身健康，瓶颈是服务端串行生成，不是工具缺陷。

## 决定

- `review_blocks.DEFAULT_WORKERS = 1`，`review_book_v2.py --workers` 默认 1。
- 保留 `--workers` 参数；在支持并发的端点上可以调高。
- 增加 `tools/preflight_model.py`：启动并行任务前先测一次并发与顺序耗时，输出建议 worker 数。
- ADR 0003 的其余决定（结构化块、证据、仲裁、advisory）保持不变。

## 考虑过的选项

- **保持默认 2**：符合 ADR 0003 的字面值，但在当前端点上会让两个 worker 互相排队，单块耗时接近翻倍，且更容易触发超时。
- **删除并发能力**：过于绝对；换到支持并发的端点时仍有价值。

## 后果

- 默认行为与当前端点能力一致；并发能力保留为显式选择。
- 审查和翻译的默认配置一致（单流），减少“并行看起来更快、实际更慢”的误判。
- 端点能力变化时，先跑 `preflight_model.py`，再决定是否调高 `--workers`。
